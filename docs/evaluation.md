# Evaluation and release gates

The versioned v1 corpus contains repository-owned synthetic React and Angular fixtures. No external
design asset or private code is included. Observations follow a strict schema covering fidelity,
correctness/reuse, viewports/states, accessibility, repair convergence/rollback, context/tokens,
latency/browser/artifacts, memory precision, and security block rates.

`pnpm evaluate` requires exactly one observation for every corpus scenario and fails when any gate in
`release-thresholds.v1.json` regresses. The generated scorecard is ignored by Git and uploaded as CI
evidence. Checked-in observations are reviewed reference inputs, not a claim that live Figma, hosts,
Slack, remote MCP, or enterprise authentication were exercised.

For a pilot release, replace reference observations with measured run output, retain provenance and
raw run/artifact hashes, review all thresholds rather than only the aggregate, and compare against the
previous accepted scorecard. Changing a threshold requires explicit review and a changelog entry.

SVG generation has a separate schema and corpus because repository framework correctness is not a
meaningful dimension for repository-free output. `svg-generation-corpus.v1.json` contains 12 owned
scenarios: simple component, form, dashboard, marketing desktop/narrow references, desktop-only
responsive checks, clean and outlined text, mixed raster/vector, path-heavy and hybrid-subtree
artwork, accessibility-sensitive controls, and unsafe script/entity inputs.

`pnpm evaluate:svg:measure` runs every safe source twice in local isolated Chromium and records
sanitization, requested/final modes, matching-reference similarity/mismatch, non-reference
responsive findings, checked/passed structural properties, runtime/network/accessibility counts,
file/byte counts, timings, peak evidence size, manifest repeatability, and verified host
compatibility. It writes `svg-generation-observations.v1.json`; measurement is an explicit evidence
refresh, not a normal fast CI step.

`pnpm evaluate:svg` validates exactly one observation per scenario and produces
`svg-generation-scorecard.json`. Its thresholds were rounded outward after the first measured local
run rather than chosen before measurement: 100% sanitization and safe completion, at least 97%
minimum measured source similarity, 70% structural-property pass rate, zero runtime/network/
accessibility findings, at most 10 KB generated bytes, a 5 second p95, and 100% repeatability and
measured compatibility. Source fidelity and responsive robustness remain separate counts and the
scorecard deliberately sets `overallQualityScore` to `null`.
