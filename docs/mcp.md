# MCP server

`smart-ui-validator-mcp` exposes the host-neutral core over MCP stdio. Stdio is the only enabled
transport in 0.4.0. Streamable HTTP must not be enabled until a deployment supplies authenticated
tenant/user identity, authorization, TLS, request limits, audit correlation, and secure token
handling.

The server publishes `smart-ui://capabilities`, validation and SVG-generation guides, run and paged
generation-context resource templates, and validation/generation prompts. `prepare_workflow` consumes the manifest generated by
`pnpm workflow:setup`, performs project inspection and idempotent design normalization once, and
returns reusable compact validation arguments. Tools use strict Zod-derived JSON schemas and accurate
`readOnlyHint`, `destructiveHint`, `idempotentHint`, and `openWorldHint` annotations. Read-like tools
do not modify a target; validation and normalization can create artifacts; repair and governed memory
mutation require explicit approval fields. No generic shell or arbitrary command tool exists.

Every filesystem input is contained within the server process working directory. Set
`SMART_UI_MCP_ROOT` to one absolute trusted workspace root when the host cannot set `cwd`; paths
outside that root fail closed. Do not set it to a home directory or another broad shared path.

Long operations pass MCP cancellation signals into the bounded core. Completed calls return compact
structured content, targeted representative findings, a deterministic terminal run record, and
artifact references. `get_findings` pages complete structured findings without repeating binary
evidence. `repair_component` accepts an explicitly approved `proposedChanges` batch from the host
agent and runs it through exact-write policy, repository checks, Chromium revalidation, convergence
analysis, and rollback. Omitting the batch selects the documented narrow background-color fallback.
`answer_question` and `continue_run` provide process-local answer handoff only; durable queues and automatic
cross-process run resumption remain host/deployment responsibilities and capability discovery says
so explicitly.

## SVG generation tools

The Phase 2 repository-free surface is intentionally small:

| Tool                     | Contract                                                                                                                                                                                                                          |
| ------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `inspect_svg`            | Sanitizes and persists bounded internal inspection evidence, then returns compact capabilities, risks, questions, recommended modes, and `smart-ui://generation-context/<id>/<cursor>`. It never exports files.                   |
| `generate_html_from_svg` | Calls the public `GenerationOrchestrator`, renders source and generated output in isolated Chromium, records source fidelity and narrow robustness separately, writes an offline report, and creates a reproducible internal ZIP. |
| `get_generation`         | Returns a compact validated record by default or the complete validated `GenerationRecord` with `responseDetail=full`; generated bodies remain artifacts.                                                                         |
| `get_generation_report`  | Returns record, preview-file, report, archive, screenshot, diff, overlay, and context references.                                                                                                                                 |
| `export_generation`      | Requires a generation ID, accepted manifest hash, exact complete generated path list, exact new empty destination, and `approved: true`.                                                                                          |

`generate_html_from_svg` accepts exact, hybrid, or semantic mode; fixed, responsive, or component
layout; an explicit source viewport; locale/theme; bounded instructions; timeout/pass limits;
compact/full response detail; and an optional complete UTF-8 host file proposal. Host files require
`hostProposalApproved: true`; only `index.html`, `styles.css`, and text SVG assets under `assets/`
are accepted in this release. Binary/base64 proposal bodies are not placed in MCP context.

The host may interpret paged design evidence, but the core parses output, validates paths and bytes,
blocks active/remote content, applies preview CSP/network denial, renders both the deterministic
fallback and proposal, and keeps the proposal only when check score and visual mismatch do not
regress beyond configuration. Repeated output and zero-pass requests retain the fallback. The
compact response reports manifest paths/hashes, small uncertainty samples, source mismatch/
similarity, finding counts, responsive-robustness findings, proposal use, artifact paths, and one
bounded next action.

MCP cancellation reaches SVG parsing, generation, preview, browser capture, comparison, report,
archive, and export checks. Calls with a progress token receive bounded stage notifications without
SVG or generated-code bodies. `generate`, `generation:export`, and `generation:delete` are additive
authorization actions; repository `repair` permission does not imply any of them.

Build and configure hosts with the absolute `apps/mcp-server/dist/index.js` path. The
[agent-first workflow](./agent-workflow.md) provides the one-command setup and retry budgets. Contract tests use
the official SDK's linked in-memory transports to list tools/resources/prompts and invoke the same
Angular inspection tool used by all hosts.
